◆ begin_sampling()

void begin_sampling ( )

Starts the sampling of all the devices.

This function performs several tasks: #. Reads which writer (see AbstractWriter) is going to be responsible for logging the data 0 -> Bluetooth, 1 -> USB, 2 -> SD card #. Reads any of the additional metadata sent over the TagCommunicator (animal name, animal species, description) #. Updates the IMU calibration structure with last recorded data from the IMU #. Resets the Queue (see Tag_Queue) to the default, empty state #. Resets each of the buffers to an empty state, with only the ID byte kept for each buffer #. Runs the pre_sampling_setup routine for the used Writer (see AbstractWriter) For these routines, the SD card writing is the one that needs a pre-sampling routine to open a file and then write to it.

◆ forward_ESP32_logging()

void forward_ESP32_logging ( )
inline

Forwards logging calls from ESP32 to the logger.

All logging calls from the ESP32 are in the form of L[message]
. Thus, when the command is L, the rest of the message will be read and sent to the logger. Additionally, thus function should not be relied upon too heavily. This solves the issue when a logging call comes in while the main() loop is happening. However, if a logging call occurs when the Teensy is currently expecting data, it will result in improper data bein written. I (Gabriel) think the only way of avoiding this is to seperate out another Serial line on the ESP32 to handle logging.

◆ initalize_devices()

void initalize_devices ( )

Initialize the sampling devices.

Based on the device settings (see DeviceEnable, ADCSettings, ADS1299Settings), the devices are initialized to prepare them for sampling. This function must be run each time update_parameters() is run, as this function is actually responsible for updating each devices settings, unlike update_parameters() which only reads the new settings but does not update the devices.

◆ update_files()

void update_files ( )

This function reads all the available files in the SD card root directory, and sends the file names over the TagCommunicator.

This function reads first the number of files present in the root directory (/) on the SD card, and then sends the filename. Thus, the sents results would look like this:

Sent to the Teensy File Index
Filename1.bin 0
Filename2.bin 1
Filename3.bin 2
Filename4.bin 3

The File Index is what is sent over the TagCommunicator to indicate on which file to do operations. The File Index is sent for download_file, delete_file to indicate which file to download or delete.

◆ update_parameters()

void update_parameters ( )

This function updates the structures that hold the settings for each sampling device.

note that this function only updates the structures for ADCSettings, ADS1299Settings, and DeviceSettings. None of the devices get updated with the new settings though. For that, initialize_devices() must be run. The data itself comes as a series of raw bytes.
