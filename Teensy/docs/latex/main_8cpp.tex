Starts the sampling of all the devices. 

This function performs several tasks\+: \#. Reads which writer (see Abstract\+Writer) is going to be responsible for logging the data 0 -\/$>$ Bluetooth, 1 -\/$>$ U\+SB, 2 -\/$>$ SD card \#. Updates the I\+MU calibration structure with last recorded data from the I\+MU \#. Resets the Queue (see \mbox{\hyperlink{classTag__Queue}{Tag\+\_\+\+Queue}}) to the default, empty state \#. {\footnotesize\ttfamily void forward\+\_\+\+E\+S\+P32\+\_\+logging (\begin{DoxyParamCaption}{ }\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [inline]}}



Forwards logging calls from E\+S\+P32 to the logger. 

All logging calls from the E\+S\+P32 are in the form of L\mbox{[}message\mbox{]}~\newline
. Thus, when the command is L, the rest of the message will be read and sent to the logger. Additionally, thus function should not be relied upon too heavily. This solves the issue when a logging call comes in while the main() loop is happening. However, if a logging call occurs when the Teensy is currently expecting data, it will result in improper data bein written. I (Gabriel) think the only way of avoiding this is to seperate out another Serial line on the E\+S\+P32 to handle logging. \mbox{\Hypertarget{main_8cpp_a1cc1a8a26d1818565992a466cd25b6b9}\label{main_8cpp_a1cc1a8a26d1818565992a466cd25b6b9}}
